# 完整 Boss 目录试玩记录

**日期：** 2026-09-04  
**范围：** 3 名模拟人类动作玩家分别覆盖全部 13 位 Boss、每位 Boss 的三个阶段。它不是浏览器自动化通关报告；实际页面观察与人类模型推断会明确分开。

## 方法

试玩依照[人类动作玩家试玩协议](human-playtest-protocol.md)：

- 初次接触普通动作玩家：295ms 中位、约 ±75ms 波动、8–12 次才稳定辨识；
- 常见熟练动作玩家：255ms 中位、约 ±55ms 波动、2–4 次建立锚点；
- 常玩弹反类动作游戏但非职业级：225ms 中位、约 ±40ms 波动、1–2 轮开始预判。

每位试玩者在 Phase I 用 220ms 实际观察一轮并对比 150ms，再通过编辑器的“练习此阶段”检查 Phase II、III 的招式池、预读与重置行为。无任何结论把脚本的逐帧点击速度当作人类成绩。

## 实际页面观察

- 三位试玩者都完成了 13/13 位 Boss、39 张阶段卡的覆盖；每位 Boss 的 Phase II、III 都通过“练习此阶段”检查。常见熟练玩家的记录还逐一验证了 26/26 次后期阶段直达练习及重置返回行为。
- 三种身份都观察到阶段卡的 `I ×1 / II ×0.5 / III ×0.5`，并确认直接练习会从 50% / 75% 架势开始，而不是强制从 0% 重打。
- 10 位机制致敬 Boss 的专属招式在本轮页面中实际显示了具名预读。三人都没有用连续机器级精准弹反伪造“人类通关”；三份试玩中均未见控制台 error / warning。
- 本轮发现的旧招式提示不一致（只显示泛化“终结段承诺”）已在试玩后修复：所有 29 套内置招式现都要求 `commitCueLabel` 和 `commitCueLeadMs`，并由配置校验器强制检查。

## 反馈与处置

- **P0：无。** 阶段练习、重置回跳、窗口切换、Boss 选择和阶段池切换均未发现阻断问题。
- **P1（已处理）：预读语言不一致。** 旧 9 招当时只有泛化提示，导致同一 Boss 在具名锚点与泛化提示间跳变。现已为旧招式补全具名预读、将其设为校验必填项，并移除了旧招式的外部作品指向命名。
- **P1（已处理）：人格仅存在于文案和曲线。** 每位 Boss 现拥有原创的程序化视觉母题：烬印、鸦羽、钟摆、弦线、绢丝、笔触、镜潮、重心线、双刃缎带、发条、雷铠、霓虹格栅和残步。它们只由 Canvas 基础图形绘制，不使用参考作品资产。
- **P2（已处理）：首见玩家面对 350–360ms 预读过紧。** 原先较短的高压招式已调整到 400ms；内置预读现在实际落在 380–450ms，配置下限为 350ms。150ms 仍定位为预判档，220ms 定位为熟悉节拍后的练习档。
- **P2（后续）：前两阶段共享通用招式。** 部分 Boss 的 Phase I / II 仍借用延迟斩、三连斩、回旋等中性练习招，降低了首阶段的专属性。下一轮内容扩充应优先为每位 Boss 增加一招早期专属变体，而不是再提高通用招的数量。

## 测试方法的下一步

以后每次目录试玩应保留“Boss / 阶段 / 看到的锚点 / 尝试次数 / 误读或按键偏差 / 150ms 与 220ms 归类”的原始记录。真实玩家数据可以逐步校正这里的保守人类模型；浏览器自动化只能验证页面行为，不能代替人类反应数据。
