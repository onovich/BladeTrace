# BladeTrace Roadmap

## 北极星

把 BladeTrace 做成一个能让设计者“看见、调出并验证”攻击节奏的轻量招式实验场：新招式由数据定义，战斗结算可复现，反馈清晰，且无需构建步骤即可在现代浏览器运行。

本路线图按依赖关系排序，不给出未经确认的日期承诺。每个阶段的验收条件比“做了多少文件”更重要。

## 阶段 0：融合原型（已验收）

**成果**

- demo1 黑金竖版视觉与上下文 Space 操作成为底板。
- demo2 的敌方 HP、时机反馈、重置、轨迹调试、自动循环、音效开关、画布点击、尾迹和额外招式已融合到 [`app/`](../app/)。
- 已加入仅本地临时生效的画布编辑模式：选段后可直接在运行时视图拖拽 P0–P3、红色 R 受击区手柄和橙色 W 内置弹反窗手柄；拆分、删除在紧凑工具条中，名称/时长/缓动/精确数值按需展开为高级参数。相邻段端点保持连续，刷新即复位。
- 已执行 Node 静态校验及真实浏览器冒烟测试，覆盖 4 次弹反 → 忍殺 → 处决、重置和画布点击弹反。
- 原始 demo 源码与设计文档已在验收后移除；融合审计保留在 `docs/`，Git 历史可追溯原始材料。

**验收门**

- 已确认 `app/index.html` 的视觉、手感与招式组合可作为唯一项目的基础。
- 已完成目录收敛：`app/` 是唯一保留的项目目录。
- 通过后才处理旧 demo 的归档/删除与目录收敛；本阶段不删除原始项目。

## 阶段 1：规则稳定与可复现验证

**目的**：把当前“可玩”变为“可以可靠比较招式”。

**工作项**

- 为全部预设定义统一的伤害、架势、内置判定窗与招式说明。
- 增加招式配置校验：连续性、时长、缓动名称、攻击终点与玩家受击区的命中关系、受击区半径范围与内置判定窗范围。
- 建立固定时间戳测试，覆盖早按、成功、逾时的终点受击/攻击落空、路径中途穿过受击区但终点不命中、忍殺、重置与自动连招；并验证调节受击区不改变弹反窗口。
- 明确并实现玩家架势是否存在；如果加入，定义它与 HP、格挡和失败后的关系。
- 补齐 320、768、1024、1440 宽度下的键盘、焦点、文本和画布可读性检查。

**完成定义**

- 任意预设能被校验并有预期结算测试。
- 同一时间戳序列在浏览器刷新率差异下产生相同战斗结果。
- README 中所有已实现机制都有实际测试或运行证据。

## 阶段 2：按拟议架构重构核心

**前置条件**：阶段 0 已验收，阶段 1 的规则测试已固定当前行为。

**工作项**

- 按 [`architecture.md`](architecture.md) 提取 `PatternCompiler`、`TrajectoryEngine` 和 `CombatSession`。
- 让 Canvas、HUD、Audio、粒子成为只消费快照和事件的 Adapter。
- 保持静态入口、视觉基线和现有控制方式不变。

**完成定义**

- 规则层不读取 DOM、不创建 AudioContext、不直接绘制 Canvas。
- 输入/渲染 Adapter 可用测试替身替换，核心结算测试无需浏览器。
- 重构前后的招式快照和浏览器冒烟结果一致。

## 阶段 3：可持久化的招式创作与练习工具

**目的**：减少手写坐标和反复改代码的成本。

**工作项**

- 将当前仅内存的编辑器升级为可导入/导出的 JSON 招式库，并保留配置版本。
- 把当前的轨迹控制点拖拽、段名称/时长/缓动编辑、拆分和删除接入配置校验、撤销/重做与实时预览。
- 显示当前段、剩余毫秒、判定窗与最近一次输入的偏差。
- 增加可分享的练习配置（招式、难度、自动循环、显示选项）。

**完成定义**

- 新增普通攻击无需修改核心战斗规则。
- 用户可以导出并重新导入一个可验证的招式配置。

## 阶段 4：扩展战斗语义

**前置决策**：确认项目是否从“普通弹反节奏模拟器”扩展到多种反制训练。

**候选工作项**

- `NORMAL`：弹反 / 格挡。
- `THRUST`：看破输入与相应窗口。
- `SWEEP`：跳跃输入与空中判定。
- 玩家架势、格挡压力、连续成功奖励与失败反馈。
- 招式串联、敌我血量结算、可选练习目标。

**完成定义**

- 每种攻击类型都有明确的输入、失败、成功、视觉提示和测试矩阵。
- 不把《只狼》专有素材、音效或品牌资产直接纳入仓库，除非权利和授权已核实。

## 阶段 5：完成度与发布准备

**工作项**

- 用原创或已授权的声音/视觉资源替换纯合成或占位反馈（如决定需要）。
- 记录浏览器支持范围、已验证分辨率、限制和隐私边界。
- 增加发布预览、变更说明和基础贡献指南。
- 设置 GitHub Social Preview 并保持 README 与架构文档同步。

**完成定义**

- 新访客能在 README 中看懂玩法、直接运行、知道当前已实现范围和限制。
- 发布前验证能在干净环境复现。

## 需要产品确认的决策

1. 玩家架势是要作为独立资源实现，还是当前阶段只保留 HP？
2. 完美弹反是否固定扣敌方 HP，还是仅累积敌方架势？
3. 目标用户更偏“招式设计/调参工具”还是“可反复游玩的训练小游戏”？
4. 阶段 4 的突刺、横扫等特殊攻击是否属于本项目范围？

这些选择会影响 `CombatRules` 的 Interface，但不影响当前融合版的验收与 Git 初始化。
