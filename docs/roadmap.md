# BladeTrace Roadmap

## 最新实现状态（2026-10-02）

- 空间弹反、普通拼刀、独立出刀／收刀、Runtime 范围与圆径编辑已实现，详见 [规则说明](spatial-parry.md)。下文旧时间窗及 W 手柄记录仅代表早期阶段，不是当前规则。
- 已接入选定的弹反、拼刀、起势录音，冷钢界面主题已落地；23 项自动测试通过，最新视觉与手感尚待浏览器验收。
- 受击与忍杀第一轮候选未获认可，留在本地试听目录；下一轮需要身体切入／闷击与致命终结感，尚未生成或接入。

## 北极星

把 BladeTrace 做成一个轻量的招式实验场与弹反练习场：动作游戏开发者能“看见、调出并验证”攻击节奏；不苛求高规格画面、但喜欢弹反的玩家能直接反复练习。新招式由数据定义，战斗结算可复现，反馈清晰，且无需构建步骤即可在现代浏览器运行。

本路线图按依赖关系排序，不给出未经确认的日期承诺。每个阶段的验收条件比“做了多少文件”更重要。

## 阶段 0：融合原型（已验收）

**成果**

- demo1 黑金竖版视觉与上下文 Space 操作成为底板。
- demo2 的时机反馈、重置、轨迹调试、自动循环、音效开关、画布点击、尾迹和额外招式已融合到 [`app/`](../app/)；敌方 HP 已在后续产品决策中移出普通攻击循环。
- 已加入仅本地临时生效的画布编辑模式：选段后可直接在运行时视图拖拽 P0–P3、红色 R 受击区手柄和橙色 W 内置弹反窗手柄；拆分、删除在紧凑工具条中，名称/时长/缓动/精确数值按需展开为高级参数。相邻段端点保持连续，刷新即复位。
- 已执行 Node 静态校验及真实浏览器冒烟测试，覆盖 4 次弹反 → 忍殺 → 处决、重置和画布点击弹反。
- 原始 demo 源码与设计文档已在验收后移除；融合审计保留在 `docs/`，Git 历史可追溯原始材料。

**验收门**

- 已确认 `app/index.html` 的视觉、手感与招式组合可作为唯一项目的基础。
- 已完成目录收敛：`app/` 是唯一保留的项目目录。

## 阶段 1：规则稳定与可复现验证（进行中）

**目的**：把当前“可玩”变为“可以可靠比较招式”。

**已完成的第一切片**

- 全部 29 个普通攻击预设现在显式定义伤害、架势收益、内置判定窗、受击区半径、类型和练习说明；其中 20 招服务于新增 Boss 的人格化阶段节奏。
- 已建立纯规则 seam `app/pattern-validation.js`：校验连续性、时长、缓动、判定窗范围、受击区范围和终点命中/落空关系；并校验 Boss 灵感信息、阶段阈值、推进倍率、ID、强调色和招式池，且可用 `resolveBossPhase(boss, posture)` 和 `calculatePhasePostureGain(phase, pattern)` 解析阶段。真实预设与无效样本均由 Node 测试覆盖。
- 已实现 13 名多阶段 Boss：3 名 BladeTrace 原创，10 名横跨 5 款动作游戏的原创机制致敬。架势在 50% 与 75% 时推进阶段；画布编辑模式可直接预览、增删和编辑阶段及其招式池。
- 后两阶段的架势推进收益已减半，保证每阶段通常至少有两次成功读招机会；阶段转换会短暂停拍、显示标题并播放提示音。每招也有比弹反窗更早出现的预读信号。
- 已实现阶段 II、III 的直接练习：从编辑器选择阶段后可直接开始实战，受击与重置都返回该阶段阈值。
- 每位 Boss 现有原创程序化视觉母题，随当前阶段强调色变化；它加强人格和读招，不引入外部游戏美术资产。
- 完美弹反已确定为只累积敌方架势；敌方 HP 不再作为普通攻击练习循环的一部分。

**工作项**

- 建立固定时间戳测试，覆盖早按、成功、阶段切换、逾时的终点受击/攻击落空、路径中途穿过受击区但终点不命中、忍殺、重置与自动连招；并验证调节受击区不改变弹反窗口。
- 根据[完整 Boss 目录试玩](boss-catalog-playtest.md)复核 13 位 Boss 的首见可读性、习得速度和阶段身份；仅在明确问题上调整轨迹、预读或数值。
- 增加“重复当前招”和“阶段混合”两种练习循环；前者服务首次学习，后者服务跨招迁移。
- 暂不实现玩家架势；如未来加入，再定义它与 HP、格挡和失败后的关系。
- 补齐 320、768、1024、1440 宽度下的键盘、焦点、文本和画布可读性检查。

**完成定义**

- 任意预设能被校验并有预期结算测试。
- 同一时间戳序列在浏览器刷新率差异下产生相同战斗结果。
- README 中所有已实现机制都有实际测试或运行证据。

## 阶段 2：按拟议架构重构核心

**前置条件**：阶段 0 已验收，阶段 1 的规则测试已固定当前行为。

**工作项**

- 按 [`architecture.md`](architecture.md) 提取 `PatternCompiler`、`TrajectoryEngine` 和 `CombatSession`。
- 让 Canvas、HUD、Audio、粒子成为只消费快照和事件的 Adapter。
- 保持静态入口、视觉基线和现有控制方式不变。

**完成定义**

- 规则层不读取 DOM、不创建 AudioContext、不直接绘制 Canvas。
- 输入/渲染 Adapter 可用测试替身替换，核心结算测试无需浏览器。
- 重构前后的招式快照和浏览器冒烟结果一致。

## 阶段 3：可持久化的招式创作与练习工具

**目的**：减少手写坐标和反复改代码的成本。

**工作项**

- 将当前仅内存的编辑器升级为可导入/导出的 JSON 招式与 Boss 库，并保留配置版本。
- 把当前的轨迹控制点拖拽、段名称/时长/缓动编辑、阶段阈值／招式池编辑、拆分和删除接入配置校验、撤销/重做与实时预览。
- 显示当前段、剩余毫秒、判定窗与最近一次输入的偏差。
- 增加可分享的练习配置（招式、难度、自动循环、显示选项）。

**完成定义**

- 新增普通攻击无需修改核心战斗规则。
- 用户可以导出并重新导入一个可验证的招式配置。

## 阶段 4：扩展战斗语义

**前置决策**：确认项目是否从“普通弹反节奏模拟器”扩展到多种反制训练。

**候选工作项**

- `NORMAL`：弹反 / 格挡。
- `THRUST`：看破输入与相应窗口。
- `SWEEP`：跳跃输入与空中判定。
- 玩家架势、格挡压力、连续成功奖励与失败反馈。
- 招式串联、敌方架势目标、可选练习目标。

**完成定义**

- 每种攻击类型都有明确的输入、失败、成功、视觉提示和测试矩阵。
- 不把《只狼》专有素材、音效或品牌资产直接纳入仓库，除非权利和授权已核实。

## 阶段 5：完成度与发布准备

**工作项**

- 按 [音效需求策划](sfx-requirements.md) 用原创或已授权的声音/视觉资源替换纯合成或占位反馈；优先拆开“架势崩溃”和“执行忍殺”两种不同语义，并保持声音可关闭、不会参与判定。
- 记录浏览器支持范围、已验证分辨率、限制和隐私边界。
- 增加发布预览、变更说明和基础贡献指南。
- 将已准备的 GitHub Social Preview 上传到仓库设置，并保持 README 与架构文档同步。

**完成定义**

- 新访客能在 README 中看懂玩法、直接运行、知道当前已实现范围和限制。
- 发布前验证能在干净环境复现。

## 已确认的产品取向

1. 当前只保留玩家 HP；玩家架势留待普通攻击练习闭环稳定后再评估。
2. 完美弹反只累积敌方架势，四次成功后进入忍殺；不扣敌方 HP。
3. 核心用户同时包含动作游戏开发者，以及对画面不苛刻、但对弹反节奏感兴趣的动作游戏玩家。默认练习界面保持简洁，编辑/观察能力按需进入。
4. 突刺、横扫等特殊反制不进入阶段 1 或 2；先保留未来扩展位，等普通攻击的测试和持久化创作闭环完成后再用单个原型验证。
5. 首次实战默认采用 220ms 练习档；150ms 修罗档定位为读懂前摇后的预判挑战，不能被解释为普通视觉反应。
