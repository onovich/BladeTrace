# BladeTrace 音效需求策划

> 状态：策划规格，尚未采购、生成或接入新的音频资产。
> 范围：当前 app 中已经存在的战斗、阶段、编辑器与系统反馈；不复刻任何参考游戏的原始音效。

## 目标

音效在 BladeTrace 中应当是第二条清晰的反馈通道：帮助玩家确认自己看见的攻击承诺、输入结果与战斗状态，也帮助开发者在编辑招式时听见一次操作是否被接受。它不能替代轨迹、判定环、文本或颜色，更不能提前泄露正确按键时机。

当前页面有少量 Web Audio 合成占位音，分别用于完美弹反、受击、阶段转换和忍殺。后续应改为稳定的事件命名与声音层级，而不是让每一句状态文字都绑定一个独立提示音。这样既能覆盖全部反馈，也不会在自动连招和画布拖拽时变成提示音轰炸。

## 设计原则

1. **视觉先行，声音确认。** 关闭音效后，玩家仍能完整练习、编辑和通关；任何成功或失败都必须保留可见反馈。
2. **承诺信号不等于答案。** 招式的预读音与可见预读信号同时出现，保持在实际弹反窗前约 350–450ms；它提示“招式已经承诺”，不能精确报出窗口边缘，更不能随难度提前。
3. **核心结果必须可区分。** 完美弹反、玩家受击、架势崩溃、执行忍殺是四个不同的语义，不能复用同一声响。
4. **少而准。** 高频 UI 变化共用少数通用音；连续拖拽不连续发声；自动循环不叠加无意义的倒计时音。
5. **原创而克制。** 使用干燥的金属、空气、布料、木质与玻璃质感建立黑金画面的声音语言。Boss 个性可有细小纹理层，但不采样、模仿或拼贴《只狼》、33 远征队、Sifu 等参考作品的具体音色、旋律或录音。

## 现状与必须拆开的语义

| 当前实现 | 当前触发 | 后续要求 |
| --- | --- | --- |
| `playDeflect()` | `PERFECT PARRY` | 保留为 `combat.parry-success`，成为最清晰、最有辨识度的短促成功音。 |
| `playHit()` | `HIT · 玩家受击`，包括致死的一击 | 拆为 `combat.player-hit` 与 `combat.player-defeated`；后者在受击瞬态之后再落一个更长的失败收束。 |
| `playPhaseShift()` | `PHASE X` 转场 | 保留为 `combat.phase-shift`，同时承载“短暂停拍、进入新节奏”的信息。 |
| `playDeathblow()` | `POSTURE BROKEN` 与 `忍殺 SUCCESSFUL` | 必须拆成 `combat.posture-broken` 和 `combat.deathblow-execute`；前者是机会出现，后者才是执行完成。 |
| 其余 `showFeedback()` / `setStatus()` | 编辑、选择、预读、早按、落空、重置等 | 归入下方通用事件，不为同一类状态文字重复制作音效。 |

## 事件音效矩阵

### P0：战斗读招与结果

这些是第一批应制作或采购的音效。它们直接影响动作玩家的读招、成功归因和失败归因。

| Cue ID | 覆盖的当前反馈 | 触发时机 | 声音简报 | 时长、变化与混音 |
| --- | --- | --- | --- | --- |
| `combat.attack-start` | `ATTACK INCOMING`、敌方剑锋开始运行 | 与攻击动画/轨迹启动同帧 | 极短的空气切入或武器起势，不要像倒计时 | 55–100ms；3 个轻微变体；低于核心结果音，约 0.22 强度 |
| `combat.commit-cue` | 每招已有的预读/承诺信号 | 与可见承诺信号同帧，在弹反窗前 350–450ms | 明确但不刺耳的“收束”提示：干净金属点、弦张力或空气吸附 | 80–140ms；每招至少 3 个通用变体；约 0.38 强度 |
| `combat.parry-success` | `PERFECT PARRY · 完美弹反` | 输入被规则确认成功时 | 双层清亮金属碰击加很短的上扬泛音；应比一切普通 UI 音更容易辨认 | 160–280ms；3 个变体且不连续重复；约 0.55 强度 |
| `combat.parry-too-early` | `TOO EARLY · 时机过早` | 过早输入被确认时 | 闷住的金属擦碰或短促低落气息；说明“有输入但不成立”，不应羞辱性刺耳 | 70–130ms；2 个变体；约 0.27 强度，300ms 内限一次 |
| `combat.attack-miss` | `MISS · 攻击落空` | 攻击在终点结算为未命中时 | 细短的掠空尾音，和受击音形成明显反差 | 90–160ms；2 个变体；约 0.18 强度 |
| `combat.player-hit` | `HIT · 玩家受击`、未致死的受击状态 | 终点命中受击区时 | 重、干、短的冲击与低频体感；不做血腥拟真 | 180–330ms；3 个变体；约 0.60 强度 |
| `combat.player-defeated` | `死 · 战斗结束，请重置后再试` | 致死受击后的 80–120ms | 从受击冲击中抽离的低沉失衡/熄灭尾音，明确表示本轮结束 | 450–750ms；1–2 个变体；约 0.46 强度 |
| `combat.phase-shift` | `PHASE I/II/III`、阶段转场提示 | 阶段转场开始，与标题和短暂停拍同步 | 向上或向外展开的金属/玻璃质感过门，留下新的空间感 | 500–850ms；按阶段和 Boss 叠加微纹理；约 0.45 强度 |
| `combat.posture-broken` | `POSTURE BROKEN · 忍殺机会` | 敌方架势达到忍殺门槛时 | 张力突然断开的裂响加短促下坠；听感是“机会被打开”，而不是胜利 | 300–550ms；2 个变体；约 0.55 强度 |
| `combat.deathblow-execute` | `忍殺 SUCCESSFUL`、大胜状态 | 玩家真正执行忍殺的输入被确认时 | 决断性的刀锋/冲击起音，接一个干净、可松一口气的收束 | 500–900ms；2 个变体；约 0.62 强度 |
| `combat.victory-release` | 忍殺后的稳定胜利状态 | `combat.deathblow-execute` 的尾部或其后 180–260ms | 非旋律化、很短的明亮余响；可以和处决音同一资产的尾部实现 | 700–1,200ms 的弱尾音；单一变体；约 0.32 强度 |
| `combat.reset` | `BATTLE RESET · 战斗已重置` | 重置动作完成、HUD 回到可开始状态时 | 清洁、向内收的复位点击；不与失败音竞争 | 70–150ms；1–2 个变体；约 0.18 强度 |

`combat.parry-window-edge` 不作为默认 P0 音效。橙色 W/判定窗本身是编辑和可视化信息，不应被一声准确的“窗口已开”蜂鸣替代成纯反应测试。未来若提供“音频时序辅助”无障碍选项，可加入 25–45ms、约 0.14 强度的极轻边缘提示，并清楚标为辅助模式。

### P1：画布编辑、练习切换与配置确认

这些声音服务创作流程，不应盖过战斗声音。相近的文字反馈共用一个语义音效；同一连串操作最多每 250ms 发一次可听提示。

| Cue ID | 覆盖的当前反馈 | 声音简报与触发规则 |
| --- | --- | --- |
| `ui.editor-enter` / `ui.editor-exit` | `CANVAS EDITOR`、开启/退出画布编辑、展开/收起高级参数 | 进入用轻微展开声，退出用同色系收束声；每次状态改变一次即可。 |
| `ui.practice-start` | `PHASE PRACTICE`、从所选阶段开始 | 短确认点加极弱起势，说明“即将练这个阶段”，不抢占随后攻击的起势音。 |
| `ui.select` | 选择 Boss、招式、阶段卡、段落，以及预览阶段 | 35–70ms 的干净点击；选择变化才播放，滑过/重复渲染不播放。 |
| `ui.confirm` | `PHASE ADDED`、`PATTERN WINDOW ENABLED`、`SEGMENT SPLIT`、有效配置保存 | 70–120ms 的轻亮确认；不使用与完美弹反相同的音高或包络。 |
| `ui.remove` | `PHASE REMOVED`、`SEGMENT REMOVED` | 60–110ms 的向下收束；保留文字说明“已删除”的具体对象。 |
| `ui.restore` | `BOSS PHASES RESTORED`、`PATTERN RESTORED` | 100–170ms 的回卷/归位感；恢复后才播放，点击但未成功恢复时不播放。 |
| `ui.reject` | `PHASE NEEDS ONE ATTACK`、`MAX PHASES REACHED`、`NO PHASE THRESHOLD LEFT`、`BOSS NEEDS TWO PHASES`、`BOSS INVALID`、`PATTERN INVALID`、至少保留一个段落 | 55–95ms 的柔和阻止音；所有校验错误共用，400ms 内节流一次，具体原因仍只看可见文本。 |
| `ui.handle-grab` / `ui.handle-release` | 开始/结束拖 P0–P3、R、W，及各项“正在调整”状态 | 抓取时一个细小摩擦点，释放并通过校验时一个轻确认点；拖动过程中不循环播放。 |
| `ui.drag-step` | W 时长、R 半径、控制点位置的可选离散刻度 | 默认关闭；若以后引入键盘/步进编辑，可每跨过有意义刻度且至少相隔 100ms 发极轻 tick。像素级指针移动永不发声。 |

### P2：系统与非声响反馈

| 场景 | 决策 | 原因 |
| --- | --- | --- |
| 音效开关的“已开启/已关闭”状态 | 保持纯视觉文本；关闭音效时绝不尝试播一个“已关闭”声音 | 用户不能听到关闭确认是正常行为，开关本身有清楚的视觉状态。 |
| 自动连续发招的等待/调度 | 不单独加倒计时或循环 tick | 避免让练习节奏被机械节拍绑架；下一招的 `combat.attack-start` 已足够。 |
| 每帧 HUD、进度条、尾迹、控制点渲染 | 不发声 | 它们是持续状态，不是离散的玩家动作或规则结果。 |
| 段落/阶段名称、剩余毫秒等文本刷新 | 不发声 | 这些内容留给视觉、读屏器与未来的显式无障碍选项。 |

## 声音语言与 Boss 个性层

核心战斗事件必须跨 Boss 保持一致：玩家一听就知道是“成功弹反”还是“自己受击”。Boss 个性只叠加在 `combat.commit-cue` 和 `combat.phase-shift` 的低音量纹理层，绝不改变弹反的语义音色，也不在每次命中时堆叠。

| 当前 Boss | 可用的原创微纹理 | 避免事项 |
| --- | --- | --- |
| 灰烬监军·烬卫 | 炭火碎裂、甲片轻响 | 真实火焰持续噪声覆盖读招 |
| 雾鸦舞姬·折羽 | 羽片掠风、丝绸回摆 | 模仿具体影视/游戏鸟鸣 |
| 铁钟守卫·鸣壁 | 低频铜钟边缘、闷击 | 长钟鸣拖住下一次输入 |
| 雷弦继承者·玄岚 | 拉紧的弦张力、干电弧 | 复刻任何知名角色的武器声 |
| 绢影宗师·蝶钗 | 绷丝、轻针、短风切 | 将优雅舞步做成高频噪声 |
| 朱绘指挥·暮颜 | 笔锋、木质指挥棒、墨色颗粒感 | 直接引用古典作品旋律 |
| 镜潮预言者·澜祷 | 玻璃水滴、反向余响 | 长混响掩盖击打时点 |
| 庭院斗师·青藤 | 布料摩擦、沉重落脚 | 做成真实拳击赛的拟真录音 |
| 展厅双刃·白纱 | 薄金属环、玻璃轻擦 | 双刀声压过核心承诺提示 |
| 机偶摄政·弦冠 | 发条、微型齿轮、断续节拍 | 过于密集的机械 click 造成误导 |
| 雷铠悔徒·银棘 | 静电、盔甲共鸣、短雷裂 | 夸张雷声掩盖输入反馈 |
| 霓虹狱长·锁环 | 数字门闩、合成栅格、锁链短响 | 使用受版权保护的科幻 UI 采样 |
| 极锋信使·零线 | 极短的闪切空气、细薄刃环 | 高频疲劳与连续残影式音效 |

这些纹理都应以原创合成、原创录制或已授权素材完成，并在最终混音中比通用核心 cue 低至少 8dB。

## 运行时行为要求

### 事件、优先级与并发

1. 未来音频层接受稳定的 cue ID 与上下文，例如 Boss ID、阶段和强度，而不是直接读取 DOM 文本。
2. P0 战斗结果可打断 P1/P2 UI 声；UI 不得打断完美弹反、受击、架势崩溃或处决。
3. 同一 cue 不允许无上限重叠：高频 cue 使用“随机但不连续重复”的变体选择，`ui.reject`、`combat.parry-too-early` 必须节流。
4. 致死受击顺序固定为 `combat.player-hit` 后再播放 `combat.player-defeated`；架势崩溃与处决是两个独立事件，中间保留给玩家完成处决输入。
5. 自动循环重新开招后只播放新的 `combat.attack-start`；重置时清掉尚未播出的过渡尾音和调度音。

### 音量、格式与无障碍

- 先保留现有总音效开关；后续若增加设置，优先分为 Master、Combat、UI 三个总线，而不是为每一个 Boss 加单独音量滑杆。
- 交付母带使用 48kHz / 24-bit WAV；网页运行时使用经过浏览器支持验证的压缩格式与回退格式。不要把未经处理的大 WAV 全部直接随首屏加载。
- 核心瞬态的峰值要留足余量，不产生削波；最终由实际浏览器、耳机和笔记本扬声器校准，而不是仅按制作软件音量判断。
- AudioContext 继续由第一次用户手势延迟创建；若浏览器不支持或用户关闭声音，所有视觉、文字、键盘和画布交互仍然完整工作。
- 不把音效作为读屏器替代品。可访问性文本、颜色以外的状态标识与可见判定窗必须持续存在。

## 验收标准

1. 每个上表中的当前反馈都能映射到一个明确 cue，或被明确标为“无声的持续/系统反馈”；不存在模糊的“也许播放某个音”。
2. 在 220ms 默认练习档和 150ms 修罗档，`combat.commit-cue` 都与视觉承诺信号对齐，且不会因难度变化提前或改成窗口边缘蜂鸣。
3. 盲听短样本时，至少能稳定区分：完美弹反、过早、受击、架势崩溃、处决、阶段转场和配置拒绝。
4. 连续自动练习 3 分钟不出现提示音堆叠、连续重复同一变体、削波，或 UI 声盖过核心结果声。
5. 声音关闭时，按现有视觉线索依然能完成弹反、阶段练习、编辑控制点、修改 R 受击区与 W 弹反窗。
6. 所有外部素材在接入前记录来源、许可证、使用范围、下载日期与文件哈希；没有明确授权的素材不进入仓库。

## 建议的交付批次

| 批次 | 内容 | 可验收结果 |
| --- | --- | --- |
| A：战斗骨架 | P0 的弹反、早按、受击、落空、阶段、架势崩溃、处决与重置 | 现有合成占位音不再混淆“机会”与“完成”。 |
| B：读招与个性 | 攻击起势、承诺信号、13 位 Boss 的低音量微纹理 | 声音帮助读招，但不成为更早的答案。 |
| C：编辑体验 | P1/P2 的选择、确认、删除、恢复、拒绝与手柄抓取/释放 | 所见即所得编辑有明确确认感，连续拖拽仍然安静。 |
| D：混音与可访问性 | 总线、节流、设备校准、音频时序辅助选项与来源清单 | 不同设备上仍清晰、可关闭、可发布。 |

实施时应先在拟议架构中的 WebAudioAdapter 中把战斗领域事件映射到这些 cue ID；当前单文件原型不需要为了接入音效提前重构。Roadmap 的发布准备阶段应以本规格为验收依据。
