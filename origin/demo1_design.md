## 2. 项目设计文档 (Technical & Product Design Document)

### 2.1 项目概述 (Overview)

#### 2.1.1 项目背景与目标
《斩迹 (BladeTrace)》是一个用于模拟与测试《只狼：影逝二度》核心“弹刀（Deflect）”机制的轻量级 HTML5 / Canvas 引擎逻辑原型。
项目通过**多段三阶贝塞尔曲线拼接**与**非线性时间缓动（Easing Functions）**，解耦招式空间轨迹与时间节奏，精准还原动作游戏中“前摇蓄力、延迟刀、瞬间爆发斩击”的变奏打击感。

#### 2.1.2 核心目标
* **空间抽象**：将敌方的刀锋攻击转化为连续可控的二维轨迹。
* **时间变奏**：支持对每段轨迹单独施加缓动曲线，实现极高自由度的“延迟刀”设计。
* **判定精准**：建立帧级/毫秒级的窗口判定机制，支持架势条（Posture）与生命值（Health）的双轨交互。

### 2.2 核心游戏机制 (Gameplay Mechanics)

```text
        ┌──────────────────────────────────────────┐
        │               敌方 (Enemy)               │
        │          [ 架势条 Posture Bar ]           │
        └────────────────────┬─────────────────────┘
                             │  攻击轨迹 (Bezier Path)
                             ▼  段落 1 -> 段落 2 -> 判定段
                       [ 刀锋光标 Cursor ]
                             │
                             ▼  [ 弹反窗口 Parry Window ]
        ┌────────────────────┴─────────────────────┐
        │               玩家 (Player)              │
        │  [ 判定区 Hit Zone ] [ 状态 Status ]       │
        └──────────────────────────────────────────┘
```

#### 2.2.1 攻击轨迹与移动规则
1. **多段前摇 (Multi-segment Windup)**：一次完整的攻击由 $N$ 段三阶贝塞尔曲线首尾相连而成（$N \ge 1$）。
   * 前 $N-1$ 段为“前摇/变奏蓄力段”。
   * 第 $N$ 段为“斩击落刀段”（最后终点为玩家判定区）。
2. **轨迹插值**：光标在当前曲线段上的进度由 $t \in [0, 1]$ 决定，实际采样进度 $t' = \text{Easing}(t)$。

#### 2.2.2 判定与状态结算
玩家按下弹反键（Space / Click）时，系统根据光标所在的位置与时间判定：

* **完美弹反 (Perfect Deflect)**：
  * **条件**：光标已进入最后一段轨迹，且剩余到达终点的时间在弹反窗口 $\delta_p$（如 150ms）内。
  * **效果**：光标沿反弹向量迅速折返敌方；播放金属火花；敌方增加架势值（+25%）；玩家不损伤。
* **招架/挡下 (Block)** *(可选扩展)*：
  * **条件**：在窗口期之外提前按住，或超出完美窗口但未受到直接伤害。
  * **效果**：玩家增加少许架势值，不扣除生命值。
* **受击/被斩 (Hit / Fail)**：
  * **条件**：光标到达终点（与玩家碰撞），且玩家未在有效窗口内成功弹反。
  * **效果**：玩家扣除生命值；**玩家架势条清空/受损**；触发画面震动与受击红闪。
* **忍殺 (Deathblow)**：
  * **条件**：敌方架势条达到 100%。
  * **效果**：冻结攻击状态，界面显示红圈“忍殺”提示，等待玩家输入击杀键。

### 2.3 核心数学模型与算法 (Math & Algorithms)

#### 2.3.1 三阶贝塞尔曲线方程
对于给定 4 个控制点 $P_0, P_1, P_2, P_3$，曲线上的点 $B(t)$ 定义为：
$$B(t) = (1-t)^3 P_0 + 3(1-t)^2 t P_1 + 3(1-t) t^2 P_2 + t^3 P_3, \quad t \in [0, 1]$$

#### 2.3.2 连续性保证 (C0 / C1 Continuity)
多段拼接时，确保第 $k$ 段的终点与第 $k+1$ 段的起点重合：
$$P_0^{(k+1)} = P_3^{(k)}$$
若需轨迹切线平滑（C1 连续），还需满足：
$$P_1^{(k+1)} - P_0^{(k+1)} = c \cdot (P_3^{(k)} - P_2^{(k)}) \quad (c > 0)$$

#### 2.3.3 缓动映射与时间推算
假设全长攻击由 $M$ 段组成，第 $i$ 段基础耗时 $T_i$。
对于第 $i$ 段，局部时间 $t_{\text{local}} = \frac{t_{\text{current}} - \sum_{k=0}^{i-1} T_k}{T_i}$，其实际空间采样参数为：
$$t' = \text{EasingFn}_i(t_{\text{local}})$$
$$P_{\text{cursor}} = \text{Bezier}(P_0^{(i)}, P_1^{(i)}, P_2^{(i)}, P_3^{(i)}, t')$$

### 2.5 接手与开发指南 (Developer Guide)

#### 2.5.1 代码模块建议组织结构
```text
src/
├── core/
│   ├── Bezier.ts          # 贝塞尔公式计算与插值
│   ├── Easing.ts          # 缓动函数库 (easeIn, easeOut, easeInExpo等)
│   └── ParryEngine.ts     # 时间轴推算与碰撞/判定窗口检测
├── entities/
│   ├── Enemy.ts           # 敌方架势条管理与招式发射
│   └── Player.ts          # 玩家输入监听与生命值/架势管理
├── config/
│   └── Patterns.ts        # 预设招式轨道配置 (延迟刀、连招等)
└── render/
    ├── CanvasRenderer.ts  # 轨迹、火花粒子与 UI 渲染
    └── ParticleSystem.ts  # 弹刀火花特效
```

#### 2.5.2 调试与开发扩展建议
1. **轨迹可视化 (Gizmo)**：在开发模式下显示贝塞尔曲线控制点（$P_1, P_2$）及连接线，便于通过拖拽可视化调整“延迟刀”轨迹。
2. **音效同步**：在轨迹进入最后斩击段（快击中前）播放“破空声（Windup Sound）”，成功弹反时播放“打铁声（Clang Sound）”，增强视听反馈。
3. **“危”字招式扩展**：在配置中加入 `type: "NORMAL" | "THRUST" | "SWEEP"`，分别对应可弹反、需看破（向前 Dash）、需跳跃的特殊攻击。
